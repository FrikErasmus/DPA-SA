What it is

A monitoring platform for businesses that run websites and servers for themselves or their clients. A small agent on each server keeps watch; your team sees everything in one web portal and mobile app.

Impendulo Monitor keeps your websites and servers healthy — and tells you the moment something needs attention.

What it does for your website

  • Checks that your site is up and responding as expected
  • Spots problems before customers do (slow, down, wrong error page)
  • Sends alerts to the right people when something stays broken
  • Keeps a clear history of what happened and when

Why it's more than "uptime"

Impendulo Monitor also watches the health of the server behind the site — disk space, services, certificates, databases, and more — so you're not just told the site is down, you get context on why.

Who it's for

  • IT teams and MSPs managing many clients or sites
  • Businesses that need reliable alerts, not noise
  • Organisations that want control of their own monitoring (self-hosted)

Why it matters

Fewer surprises, clearer signals, faster recovery. Impendulo Monitor watches what matters, alerts the right people, and gives your team the context to act — without drowning you in noise.

What Impendulo Monitor monitors

Comprehensive checks across your servers, websites, applications, and data — with clear actions when something goes wrong.

Server health (the machine behind your site)

  • CPU — when the server is overloaded for too long
  • Memory (RAM) — when the server is running out of memory
  • Disk space — per drive/volume, before you run out of room
  • Network — can the server reach the internet or other hosts (ping)
  • Network speed — download/upload below your minimum

Websites & online services

  • Websites — is the site up, responding, and returning the right status code
  • APIs — connectivity, status codes, response body checks, and slow responses
  • SSL certificates — expiry warnings, expired certs, and TLS/connectivity problems

Applications & infrastructure (mainly Windows servers)

  • Windows services — is each critical service running (can auto-restart before alerting)
  • IIS app pools & sites — web hosting components running as expected (can auto-recover)
  • Event logs — Windows Event Log or Linux journal entries you care about (errors, warnings, etc.)

Files, folders & databases

  • Directories — missing folders, empty folders, or expected files not present
  • SQL / database checks — can we connect, did the query return what we expected (rows, no rows, or a value threshold)
  • Custom scripts — PowerShell or SQL checks you define for your own business rules
